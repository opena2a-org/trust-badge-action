# Failed runs

A package with no trust profile does not fail the run: the README is left as it is and `updated` is `false`. The run fails, with the README unchanged and no outputs set, when:

- `registry-url` is not an `http` or `https` URL. The run fails before the registry lookup, with an error that names the input and quotes the value: `Action failed: registry-url not-a-url is not an http or https URL.` An empty value is read as the default, `https://api.oa2a.org`.
- `create-pr` or `auto-merge` has a value other than `true`, `True`, `TRUE`, `false`, `False` or `FALSE`, the values `getBooleanInput` in `@actions/core` accepts. The run fails before the registry lookup, with an error that names the input and quotes the value: `Action failed: Input create-pr is "yes"; accepted values: true, True, TRUE, false, False, FALSE.` An empty value is read as the default `action.yml` gives the input.
- The registry does not answer. A lookup with no answer or only part of one, a 429 or a 5xx is tried 3 times, each attempt allowed 15 seconds, with pauses of 2 and then 4 seconds: against a registry that does not answer, the run fails after about 51 seconds.
- The registry answers with another unexpected status, or with a body that is not JSON or not a trust profile (an object with `agentId`, `trustScore` and `trustLevel`). For a failing status, the log quotes the registry's `error` text when it sends one.
- The package name contains `/` (a scoped npm name or an `owner/repo` name) and the lookup returns no agent id in UUID form. The registry serves no badge image by name for such a package, so there is no badge to write.
- The badge image's score or level differs from the lookup's; each run prints both and fails until the registry's image agrees. After the lookup, the action fetches the image it is about to write and reads its title, `Trust: <score> | <level>`: `<score>` has to be the lookup's trust score times 100 with the fraction dropped (0.2166 reads 21), and `<level>` the lookup's level. A title in another form, such as the registry's `Trust: not found`, fails the run as well. The image is fetched as the lookup is: no answer or only part of one, a 429 or a 5xx is tried 3 times, each attempt allowed 15 seconds, with pauses of 2 and then 4 seconds; any other status, 404 included, fails the run at once.
- `readme-path` resolves outside the workspace: the checkout in `GITHUB_WORKSPACE`, or the process working directory when that variable is unset. The failure names the input and the workspace: `Action failed: readme-path ../outside/README.md resolves outside the workspace /home/runner/work/my-repo/my-repo. Give a path inside the repository.` A `readme-path` inside the workspace that names no file does not fail the run: it logs a warning and `updated` is `false`.

The run also fails with no outputs set when GitHub refuses the commit or the pull request (branch protection, a token without `contents: write`, a README that changed on the branch since the run checked out). The README is then updated in the workspace only. The error names the branch and repeats GitHub's message: `Failed to commit the README to branch <branch>: <message>`, or with `create-pr: true`, `Failed to open the pull request into <branch>: <message>`. In that mode a refusal can come after the badge commit to the badge branch, `opena2a/update-trust-badge` or `opena2a/update-trust-badge-<branch>`, which then holds the badge with no pull request open.
